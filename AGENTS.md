# AGENTS.md

Flutter school project: a contact-book app ("Buku Kontak") with an Indonesian UI. Dependencies are `cupertino_icons`, `firebase_core`, and `cloud_firestore` — no state-management or other packages; persistence, validation, and routing are hand-rolled.

## Names and versions
- Package name is `kontak_form` (folder is `Fahri_BukuKontak`; Android `android:label` is `kontak_form`; applicationId `com.example.kontak_form`). Use `kontak_form` in imports and package references, never the folder name.
- SDK: Dart `^3.13.1`, Flutter 3.47.2 stable.

## Commands
- `flutter analyze` — clean, no issues.
- `flutter test` — passes (+3): `test/widget_test.dart` holds pure-Dart unit tests for the `Contact` model (`toMap`/`fromMap`). There are intentionally **no widget tests** — the Kontak tab builds a real Firestore `StreamBuilder`, which needs a Firebase app/mock, so pumping `MyApp` in a widget test would throw.
- `flutter run` / `flutter build apk` — standard. Firebase is configured for **Android + Web only** (`firebase_options.dart` throws on macos/windows/linux desktop).

## Firebase setup (required for this app to run)
- Firebase is initialized in `main()` via `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)` before `runApp`; there is no `main` without this now.
- `lib/firebase_options.dart` and `android/app/google-services.json` are generated by `flutterfire configure` (install: `dart pub global activate flutterfire_cli`, then `firebase login --no-localhost` once). Regenerate after creating a new Firebase project; the app is one Firebase project (`buku-kontak-fahri`).
- Firestore database runs in **test mode** (open rules; expires ~30 days after creation). Collection: `kontak`.
- `android/app/src/main/AndroidManifest.xml` carries `<uses-permission android:name="android.permission.INTERNET"/>` — required for Firebase on release builds.

## Code structure
All app code lives in `lib/main.dart` (~800 lines). There are no feature directories; every widget, page, and the model are in that one file. Add new code there unless you also refactor.
- `Contact` model: `id` (Firestore document id), `name`, `email`, `phone`, `category` (`String?`); converts via `Contact.fromMap(String id, Map<String, dynamic>)` / `Contact.toMap()`. Fields that are missing/null in a doc default safely (`''` / `null`).
- Contacts are stored in Firestore through the top-level **getter** `_kontakRef` (`FirebaseFirestore.instance.collection('kontak')`). **Keep it a getter, not a top-level `final`** — a `final` would evaluate `FirebaseFirestore.instance` at import time and break the unit tests, which import `main.dart`.
- `_favorites` is a module-level in-memory list (Favorites tab) — **not persisted**, out of LKM scope, and the only remaining in-memory state.
- Pages: `HomePage` (TabBar: Kontak / Favorit + drawer), `ContactPage` (nested StreamBuilders: outer search stream, inner `_kontakRef.snapshots()`; loading spinner while `!hasData`, error text on `hasError`; delete via confirm dialog → `doc(id).delete()`), `FavoritePage`, `AddContactPage` (Form validation → `_kontakRef.add` with SnackBar "Data berhasil disimpan"), `AddFavoritePage` (plain `TextField`s, in-memory only), `EditContactPage` (takes **only** `Contact` — never an index; `_kontakRef.doc(id).update`), `AboutPage` (loads `assets/profile.jpg`).
- All Firestore writes (`add`/`delete`/`update`) are wrapped in `try-catch` and report via `ScaffoldMessenger` SnackBar, plus an early `id.isEmpty` guard on delete/update.
- SnackBar uses the root `ScaffoldMessenger`, so it stays visible after the form page pops. `mounted` guards follow the pattern below.

## Conventions & lint gotchas
- UI strings and git commit messages are in Indonesian (e.g. `feat: simpan kontak ke Cloud Firestore`). Keep new UI text in Indonesian.
- Material 3 via `ColorScheme.fromSeed`; `AppBar` background uses `colorScheme.inversePrimary`.
- `use_build_context_synchronously` in Flutter 3.47 distinguishes the two cases: guard **`State.context`** (used inside a State *method*) with `if (!mounted) return;`, and guard a closure **`BuildContext` parameter** (e.g. `context` captured inside `build(BuildContext context)`) with `if (!context.mounted) return;`. Mixing the two styles trips the lint.
